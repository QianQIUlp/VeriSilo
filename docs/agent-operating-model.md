# VeriSilo 主脑 Agent 与执行 Agent 协作协议

状态：**规范性工作协议**。本文规定复杂阶段任务如何拆分、执行和验收，避免主脑完全放任或重复执行全部劳动两个极端。

## 第二次主脑纠偏：审阅不等于重做

在早期阶段结果审阅中，主脑曾把“不直接相信执行 Agent”延伸为倾向重新检查完整实现和测试。用户明确纠正了成本模型：如果主脑把执行 Agent 的劳动从头做一遍，就失去了委派意义，而且第二次完整执行仍不能消除未知问题。

因此，主脑的职责是守住语义、架构、范围和 Gate，检查结果包是否足以支持结论；执行 Agent 的职责是完成实现和完整验证。主脑既不能只看一句“全部通过”就放行，也不能默认成为第二个劳动力 Agent。需要补证时，优先把一个最小、针对性任务退回执行 Agent。

## 角色

### 主脑 Agent

主脑持有跨阶段上下文，负责：

- 理解用户真实目标、产品北极星和现有架构；
- 判断当前最大风险和最有价值的下一步；
- 在执行前冻结目标、范围、验收、停止条件和输出格式；
- 接收执行结果后检查语义、范围、证据与结论是否匹配；
- 给出 `passed`、`conditional`、`failed` 或 `blocked` Gate；
- 生成下一阶段执行提示词，并防止任务漂移。

主脑的主要产物是决策和可执行任务合同，不是大量重复终端日志。

### 执行 Agent

执行 Agent 在冻结范围内负责：

- 检查实际仓库和运行环境；
- 实现代码、测试、夹具和文档；
- 运行任务要求的验证并生成 run-id、报告和摘要；
- 保持改动范围和 Git 历史可解释；
- 如实报告失败、未覆盖边界和需要新授权的事项；
- 返回供主脑决策的证据包。

执行 Agent 不得自行改变产品方向、降低 Gate、越过停止条件或宣布开放下一产品阶段。

## 标准工作流

```text
用户目标
→ 主脑读取北极星、架构决策和当前状态
→ 主脑冻结任务合同
→ 执行 Agent 实现、测试、提交、报告
→ 主脑进行成本受控审阅
→ Gate 决策
→ 下一任务或最小补证
```

## 任务合同必须包含

- **目标**：本阶段要证明或交付的一件核心能力。
- **成功标准**：可由执行结果明确回答的 Gate。
- **允许范围**：可修改的模块、数据和文档。
- **禁止范围**：不得提前接入或顺手重构的层。
- **环境条件**：例如原生 Windows、固定资产、离线模式。
- **验收矩阵**：正常、失败和关键反例。
- **停止条件**：继续工作会越权、缺少外部条件或需要架构决策的情况。
- **交付格式**：文件、测试、run-id、commit、工作树和边界。

任务开始后不应临时增加与核心结论无关的产品级要求。新发现只有在直接推翻当前 Gate、破坏不可恢复数据或使下一阶段建立在错误基础上时，才成为当前阻断；其他事项进入 backlog。

## 执行证据包

执行 Agent 的最终结果至少应包含：

1. 运行环境和基线 commit；
2. 逐项 Gate 结果；
3. 修改范围和关键实现选择；
4. 实际运行的验证与结果；
5. run-id、报告摘要或机器可读证据位置；
6. 本地提交和证据 manifest 绑定；
7. 工作树、残留进程和外部副作用状态；
8. 已知边界、未验证项和停止原因；
9. 明确的 `passed`、`failed` 或 `blocked` 执行结论。

自摘要、测试通过和工作树干净都不是单独充分证明；它们必须与任务要求的行为证据对应。

## 主脑的成本受控审阅

主脑默认执行以下检查：

1. 逐项对照冻结任务，确认没有遗漏核心交付；
2. 检查是否改变用户语义、产品优先级或领域模型；
3. 检查是否触碰禁止范围或把后续层提前混入；
4. 检查测试和 run-id 是否真正对应所声称的 Gate；
5. 检查结论是否把 `configured`、`applied`、`observed` 或 `verified` 混用；
6. 检查 commit、manifest、工作树和已知边界是否自洽；
7. 将非阻断风险放入明确 backlog，而不是继续扩大当前任务。

主脑默认**不**：

- 把执行 Agent 的完整实现重新写一遍；
- 重跑全部浏览器、平台或长周期测试；
- 重新生成所有 Artifact 和证据；
- 在任务结束后才发明新的完整验收矩阵；
- 因无法证明“没有任何未知问题”而无限阻止推进。

## 何时需要补证或最小检查

出现以下情况时，主脑应优先向执行 Agent 发出一个最小补证任务：

- 核心 Gate 只有结论，没有对应测试或证据；
- 报告内部值互相矛盾；
- 实现明显绕过任务要求；
- 平台、资产或 commit 与任务基线不匹配；
- 结论超出了明确覆盖范围。

只有在证据矛盾无法通过结果包解释、风险直接影响当前 Gate，且一个小型只读检查能够显著提高决策信息时，主脑才进行针对性检查。检查范围必须小于执行任务本身；否则应退回执行 Agent，而不是把主脑变成第二个执行者。

## 两个禁止极端

### 完全不看

执行 Agent 写“全部通过”不等于 Gate 自动通过。主脑仍需检查语义、范围、证据链和剩余边界。

### 从头重做

独立再执行一遍全部实现和测试只增加有限置信度，却消耗第二遍成本，并不能证明不存在更深问题。主脑必须按信息收益选择检查深度。

## Gate 输出格式

主脑接收结果后的输出固定为：

1. **结论先行**：通过、条件通过、不通过或阻塞；
2. **语义与范围**：是否解决正确问题、是否越界；
3. **核心 Gate**：逐项结果与证据类别；
4. **阻断项**：只列必须补充的事项；
5. **Backlog**：不阻止本阶段的边界；
6. **推进决策**：下一阶段是否开放；
7. **下一执行任务**：只有需要时才提供冻结提示词。

措辞应明确是“基于执行 Agent 提交证据的 Gate 判断”，除非主脑确实完成了额外独立验证。
