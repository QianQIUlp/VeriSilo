Together with the Preview verification of targets, independent operations and late responses, this covers the selection behavior.

For the real backend run, network and restore scope, see the [native acceptance record](managed-concurrency-2026-09-28.md).

In the implementation, the UI uses the `siloId` wrapper of `DesktopStatus.sessions` to target each Silo card, the identity details, stop, re-observe and cold restore. `focusedSiloId` controls only the selected state. Each single-Silo operation sets its own busy flag. A Vault lock invalidates all unfinished UI callbacks. A failure record with no residual occupancy is shown as failed but does not occupy a concurrency slot, and the backend remains the final start guard. When there are multiple sessions, `activation` is `null`, and the UI does not take the first entry of the collection to pose as the single session. Preview A/B/C use different simulated Profile directories, Seeds and Artifact digests.
