# Known leaks and limits

- Independent `user-data-dir` values isolate browser persistence, not the operating system, hardware, network stack, installed fonts, behavior, payment data, or account graph.
- Chromium proxy configuration can still have browser/network edge cases. A successful configuration write or TCP preflight is not an exit-IP guarantee.
- The companion's MAIN-world code can be observed by a page and may inject after page code has run.
- V0.5 Labs can temporarily wrap only Workers created after opt-in and only the same-origin/blob classic constructor path. A page may have cached the native constructor earlier; existing Workers, module Workers, cross-origin Workers, SharedWorkers and Service Worker execution remain outside coverage. A passing self-test is therefore `best_effort`, not `verified`.
- Labs canary scans detect only evidence visible through bounded current-origin checks: Window/document/URL, same-origin iframe content, page-visible Cookie/storage values, matching tabs and exposed Service Worker registration URLs. They cannot inspect Worker or Service Worker memory, HttpOnly Cookie values, browser-internal Cookie writes, or every Set-Cookie response. Absence of a detected canary is not proof that those paths are isolated.
- Cookie repository virtualization and comprehensive Set-Cookie interception are unavailable in the stock MV3 companion. Their Labs cards are unselectable `unsupported`; use a desktop Silo with an independent `user-data-dir` for browser-managed Cookie and site-data separation.
- A page can forge a fail-stop Labs event because MAIN-world evidence is page-observable. This can only force restoration and site disablement; it cannot promote an experiment to `best_effort` or `verified`. A hostile page can also interfere with restoration, which is recorded as a failed restore rather than hidden.
- Browser features and permissions vary by Chrome/Edge version and enterprise policy. Runtime state must expose control conflicts and verification failures.
- Local vault encryption protects VeriSilo metadata at rest from casual file inspection. It does not protect against an attacker controlling the browser process, operating system, or signed extension updates.
